# РОЙ

Образовательная платформа о природных явлениях. Каждый урок — работающая
симуляция: ничего не проигрывается по таймлайну, всё вычисляется из правил
каждый кадр, поэтому одна и та же сцена никогда не повторяется дважды.

Статический сайт без сборки. Открывается двойным кликом по `index.html`.

---

## Как запустить

**Локально, самый простой способ.** Двойной клик по `index.html`. Всё работает
по протоколу `file://`: ES-модулей нет, локальные файлы через `fetch` не
загружаются, данные уроков лежат в обычном `.js`.

**Через локальный сервер** — если нужно проверить `robots.txt`, `sitemap.xml`
или относительные ссылки так, как их увидит хостинг. PowerShell, без Node
и Python:

```powershell
$root = "C:\Проэкты\roy"
$listener = [System.Net.HttpListener]::new()
$listener.Prefixes.Add("http://localhost:8080/")
$listener.Start()
Write-Host "http://localhost:8080/ — Ctrl+C для остановки"
while ($listener.IsListening) {
  $ctx = $listener.GetContext()
  $rel = [Uri]::UnescapeDataString($ctx.Request.Url.AbsolutePath.TrimStart('/'))
  if ($rel -eq '') { $rel = 'index.html' }
  $path = Join-Path $root $rel
  if (Test-Path $path -PathType Leaf) {
    $bytes = [IO.File]::ReadAllBytes($path)
    $ext = [IO.Path]::GetExtension($path).ToLower()
    $types = @{ '.html'='text/html; charset=utf-8'; '.css'='text/css; charset=utf-8';
                '.js'='application/javascript; charset=utf-8'; '.svg'='image/svg+xml';
                '.png'='image/png'; '.xml'='application/xml'; '.txt'='text/plain; charset=utf-8' }
    if ($types.ContainsKey($ext)) { $ctx.Response.ContentType = $types[$ext] }
    $ctx.Response.OutputStream.Write($bytes, 0, $bytes.Length)
  } else { $ctx.Response.StatusCode = 404 }
  $ctx.Response.Close()
}
```

**Сборка production-версии не нужна.** Нет ни минификации, ни бандлера:
файлы отдаются как есть. Если захочется минифицировать — это опционально
и никак не влияет на работу.

### Почему `lessons.js`, а не `lessons.json`

По протоколу `file://` браузер запрещает `fetch` локальных файлов, а сайт
обязан открываться двойным кликом. Поэтому данные лежат в `.js` и
присваиваются в `window.ROY_LESSONS`.

Если сайт размещается на хостинге и JSON нужен как формат обмена с CMS,
переключение занимает две правки:

1. Переименовать `data/lessons.js` в `data/lessons.json`, убрав обёртку
   `window.ROY_LESSONS = ` и точку с запятой в конце.
2. В каждой странице заменить `<script src="data/lessons.js">` на загрузку:

```js
fetch('data/lessons.json')
  .then(function (r) { return r.json(); })
  .then(function (data) { window.ROY_LESSONS = data; start(); });
```

После этого сайт перестанет открываться по `file://` — только через сервер.

### Плавность на любом железе

Качество — одно число от 0 до 1, на которое сцены умножают всё, что можно
урезать. Ступеней пять: **1 → 0,75 → 0,5 → 0,35 → 0,22**. Раньше их было две
(«полное» и «половина»), и это плохой ответ обеим сторонам: слабой машине мало,
средней обидно.

Что меняется на каждой ступени:

- **число частиц** — `ROY.count(n)`;
- **шаг расчётной сетки** — `ROY.cell(base)`; клетка крупнее ровно настолько,
  чтобы работы стало меньше во столько же раз, ведь площадь растёт как квадрат;
- **плотность пикселей холста** — потолок `1 + quality`, то есть от 2,0 до
  1,22. На телефоне это главный выигрыш: холст на ретине втрое больше по
  площади, а заливка бумагой идёт по всем пикселям каждый кадр;
- **сколько декоративных миниатюр считается за кадр** — от трёх до одной.

**Стартовая ступень — догадка по устройству**, а не измерение:
`hardwareConcurrency ≤ 2` или `deviceMemory ≤ 2` → сразу 0,5; телефон (узкий
экран и dpr ≥ 2) → 0,75; всё остальное → полное. Где браузер эти числа не
сообщает, считаем машину приличной — иначе мощный компьютер зря получил бы
урезанную картинку.

**Дальше решает измерение, и только вниз.** Кадр длиннее 21 мс (это уже меньше
48 кадров) на протяжении 700 мс — ступень вниз, потом 1,2 с на то, чтобы
система устоялась. Первые 1,5 с не судим вовсе: там раскладка и шрифты.

Наверх регулятор не возвращается никогда. Причина не в лени: возврат выглядел
бы как хлопок — частицы появляются из ниоткуда, — и при любой ошибке измерения
начались бы качели.

Судим по длительности отдельных кадров, а не по среднему fps за секунду:
секунда со средними 60 кадрами и парой провалов по 120 мс для глаза хуже, чем
ровные 50.

#### Первые кадры страницы

Отдельная история, и самая коварная: средняя цена кадра её не ловит.

Стая спавнилась тесным узлом радиусом в шестую часть холста. Две с половиной
тысячи птиц в таком круге — это сотни соседей в каждой клетке сетки, и **первые
двадцать шагов стоили 42 мс вместо восьми**. На экране это выглядело как рывки
ровно в тот момент, когда человек только открыл главную.

Исправлено двумя правками:

- **спавн по всему насесту**, а не узлом: плотность на старте падает впятеро;
- **потолок просмотренных кандидатов** (80 на птицу), чтобы цена кадра вообще
  перестала зависеть от плотности — хоть на старте, хоть когда ползунок
  «сплочённость» выкручен на максимум.

Со вторым есть тонкость, на которой я сначала ошибся. Клетки обходились от
угла, и потолок отсекал соседей всегда с одной стороны: симметрия ломалась, и
**стая схлопывалась в комок — разброс падал с 224 пикселей до 31**. Лечится
порядком обхода: сначала своя клетка, потом кольцо вокруг. Ближайшие соседи
почти всегда лежат в своей же клетке, так что перекоса больше нет.

Итог: первые двадцать кадров стоят 5,5 мс против 4,5 установившихся — разница
в 1,2 раза вместо пятикратной. Разброс стаи на двенадцати тысячах шагов гуляет
между 150 и 290 пикселями и не схлопывается.

### Первый экран: сначала сборка, потом текст

Страница открывается не заголовком. Птицы летают свободно около 0,4 с, потом
за 1,5 с складываются в надпись «24 явления». Текст и ползунки в это время
спрятаны. Прокрутка вниз рассыпает надпись обратно в стаю и выводит текст.

Четыре решения, без которых это ломается:

- **Текст прячется встроенным скриптом сразу после разметки, а не общим
  скриптом внизу.** Иначе между разбором страницы и запуском скриптов
  заголовок успевает мигнуть. Условие там то же, что у движка: системная
  настройка движения плюс настройка сайта; всё в `try/catch`, и если скрипты
  отключены — текст просто останется на месте.
- **Появление текста висит на обычном таймере, а не на последнем кадре
  анимации.** В фоновой вкладке кадры не идут вовсе, и привязка к анимации
  означала бы, что текст не появится никогда.
- **Показанный текст обратно не прячется.** Раньше он уходил и возвращался по
  порогу прокрутки; при новом порядке это выглядело бы как мигание — отлистал
  к самому верху, и заголовок исчез посреди чтения.
- **Надпись стоит выше центра холста** (`cy: 0.26` у `samplePoints`). По
  центру буквы легли бы ровно на заголовок, который после вступления
  остаётся на экране.

При выключенном движении вступления нет вовсе: страница сразу такая, какой её
увидят после него, только стая стоит.

### Стая на первом экране: почему её так много

Из этих же птиц складывается надпись «24 явления», а на две строки букв
семисот не хватало — выходило решето. Сейчас на широком экране 2600 птиц,
на среднем 1700, на узком 900.

Столько получилось поставить не наращиванием бюджета, а тремя правками.
Все три измерены на холсте 1280×860, бюджет кадра 16,7 мс:

| птиц | радиус обзора | обычная стая | надпись |
|---|---|---|---|
| 1400 | 115 | 6,71 мс | 0,26 мс |
| 2000 | 115 | 8,39 мс | 0,36 мс |
| 2000 | 70 | 6,29 мс | 0,35 мс |
| **2600** | **60** | **6,66 мс** | **0,47 мс** |
| 3000 | 55 | 9,54 мс | 0,54 мс |

1. **Меньше радиус обзора.** Это не экономия в ущерб правде, а наоборот: чем
   плотнее стая, тем ближе к птице те самые семь соседей, за которыми она
   следит. Зато поиск дешевеет квадратично по радиусу. 2600 птиц с радиусом
   60 стоят ровно столько же, сколько 1400 со 115.
2. **В собранной надписи соседи не ищутся вовсе.** Силы стаи там всё равно
   умножаются почти на ноль, а поиск — самая дорогая часть шага: 4,35 мс
   превратились в 0,26.
3. **Чернила привязаны к числу птиц.** Кладут их все птицы вместе, а смывает
   одна заливка. Удвоив стаю и не тронув смыв, я получил серый холст вместо
   бумаги. Теперь плотность штриха и скорость смыва меняются так, что их
   произведение постоянно: тон бумаги одинаков и на шестистах птицах, и на
   двух с половиной тысячах.

На слабой машине автоснижение качества урежет стаю вдвое — это общий
механизм движка, он был и раньше.

### Страница урока: две колонки, две прокрутки

Правая колонка со сценой и параметрами прокручивается сама по себе
(`overflow-y:auto` плюс `max-height` в высоту экрана). Без этого низ панели
недостижим: липкий блок выше экрана просто обрезается, и до последнего
ползунка не добраться никаким скроллом. Курсор слева листает страницу,
курсор справа — панель. В одну колонку (уже 980 px) делить нечего, там
ограничение снимается.

### Почему параметры не меняются от прокрутки

Раньше параметр уезжал сам, стоило абзацу попасть в середину экрана. На
словах это «читатель не представляет описанное, а видит», на деле —
«ползунки живут своей жизнью»: прокрутил текст туда-сюда, и сцена дёргается
без твоего участия, а выставленное вручную значение затирается.

Теперь у каждого такого абзаца стоит кнопка **«Показать»**. Она делает ровно
то же самое и с тем же плавным переходом за полторы секунды — но тогда,
когда её попросили. Подпись на кнопке взята из данных урока, а если её нет,
собирается из названия параметра: «Показать: угол ветвления → 38».

Отметка текущего абзаца на прокрутке осталась — она только подсвечивает, где
читатель, и ничего не трогает в сцене.

### Поиск по каталогу

Индекс собирается в браузере из самих уроков: заголовок, подводка, все
абзацы, подписи к рисункам и вопросы. Отдельного индекса на диске нет —
расходиться с содержимым ему не с чем.

Две вещи стоит знать при правке:

- **Словоформы.** Поиск ищет подстроку, а русский язык склоняется, поэтому
  слово, которого нет нигде в каталоге, укорачивается с хвоста — максимум на
  три буквы и не короче четырёх: так `светляк` находит «светлячков». Основа
  выбирается один раз по всему каталогу, а не отдельно в каждом уроке.
  Иначе `скворц` в уроке про волны ужмётся до `скво` и урок найдётся по
  слову «сквозь» — это и случилось в первой версии.
- **`window.ROY_KEYWORDS`** в конце `data/lessons.js` — научные термины,
  которых в тексте урока нет: у муравьёв написано «пахучий след», а искать
  будут «феромон». Эти слова участвуют только в поиске; если урок нашёлся
  по такому слову, карточка честно пишет, по какому именно.

сцен через `IntersectionObserver`, полная остановка при уходе на другую
вкладку, ретина через `devicePixelRatio`.

### Отладка симуляций

Симуляции проверяются в `lab/harness.html`:

```
lab/harness.html?sim=boids&warm=3000&motion=on
lab/harness.html?sim=reaction&warm=4000&f=0.029&k=0.057
```

- `?sim=` — какая симуляция: `boids`, `reaction`, `fern`, `waves`, `samara`,
  `traffic`, `fireflies`, `sand`, `ants`, `snowflake`, `fish`, `bees`, `cracks`,
  `canopy`, `lightning`, `river`, `shell`, `dunes`, `locust`, `swarm`,
  `clouds`, `flame`, `rivulet`, `soapfilm`
- `?warm=N` — прогнать N шагов физики до первой отрисовки
- `?bare=1` — спрятать панель, чтобы снять чистый кадр
- `?motion=on|off|auto` — переопределить системную настройку движения
- `?graphics=low|auto` — переопределить качество
- любой параметр симуляции по имени, например `&coh=0.2`

`warm` нужен потому, что headless-браузер за секунды виртуального времени
отдаёт единицы кадров `requestAnimationFrame`: без прогрева на скриншот
попадает стартовая расстановка, а не результат работы правил.

Стенды `lab/a11y.html`, `lab/search.html` и `lab/fade.html` открывают страницы
сайта в iframe и читают их содержимое. По `file://` каждый документ для
браузера — отдельное происхождение, поэтому в headless им нужен флаг
`--allow-file-access-from-files`; без него `contentDocument` равен `null` и
стенд молча показывает пустую таблицу.

Ещё две ловушки, если писать такой стенд:

- `scrollTo(0, y)` в headless не доезжает: у страницы `scroll-behavior:smooth`,
  а плавную прокрутку крутят кадры, которых почти нет. Нужно
  `scrollTo({top:y, behavior:'instant'})`.
- Событие `scroll` после этого приходит не всегда, поэтому стенд посылает его
  сам через `dispatchEvent`: проверяется логика обработчика, а не
  расторопность безголового браузера.
- Всё, что анимируется переходом или задержкой, в headless так и остаётся в
  начальном состоянии. Проверять надо не применённое значение, а объявленное
  правило — через `document.styleSheets`.

### Проверка узких экранов

Headless Edge на Windows не отдаёт вьюпорт уже примерно 490 пикселей: при
`--window-size=390` страница всё равно верстается на 492 и снимок выходит
обрезкой широкой версии, а не мобильной вёрсткой. Поэтому мобильный вид
смотрим через `lab/mobile.html?p=index.html` — он открывает страницу в
iframe шириной 390 и 768.

## Что нужно подключить перед запуском

Сайт честно показывает, чего в нём нет. Ни одна кнопка не притворяется
работающей.

| Что | Где | Что сделать |
|---|---|---|
| Домен | `robots.txt`, `sitemap.xml`, все `canonical` и `og:url` | заменить `roy.example` |
| Приём заявок | `teachers.html`, форма лицензии | обработчик на сервере; **повторить всю валидацию на сервере заново** |
| Оплата | `pricing.html`, блок «Оплата» | провайдер (Przelewy24, Stripe, PayU), вебхук подтверждения, выдача доступа |
| Аккаунты | `account.html`, вход по коду | настоящая авторизация; сейчас это заглушка без проверки |
| Разграничение доступа | `assets/js/app.js`, `ROY.hasAccess` | сейчас платные уроки закрыты на клиенте; после подключения аккаунтов проверка обязана быть на сервере |
| Юридические тексты | `privacy.html` | проверка юристом; текст написан разработчиком и помечен как шаблон |
| Материалы для школ | `teachers.html` | рабочие листы, вопросы, таблица тем |

Переменных окружения у статической сборки нет, поэтому `.env.example` не
нужен. Он появится вместе с бэкендом — и ключи провайдера оплаты должны
жить только там, никогда во фронтенде.

### Шрифты

**Oswald** (`--display`) — только крупное: h1, h2, логотип, цены, подписи
шагов. **Golos Text** (`--sans`) — всё остальное, включая h3, h4 и заголовки
карточек. **IBM Plex Mono** (`--mono`) — цифры и подписи к осям.

Иерархию держит контраст ширины: узкий гротеск против обычного. Второй кегль
и второй цвет для этого уже не нужны. Переменная называется `--display`, а не
`--serif`, потому что засечек здесь нет — Oswald это гротеск.

Две настройки, без которых узкий гротеск выглядит хуже, чем он есть:
`letter-spacing:0` у h1 и h2 (буквы и так тесные, отрицательный трекинг их
слепляет) и `line-height:1.06` (у Oswald короткие выносные, и на обычных 1.15
между строк зияет).

Цитаты учителей и вопросы к классу намеренно набраны не заголовочным
шрифтом: узкий гротеск на этих местах читается как крик.

### Кнопки и меню

Пункты меню — не кнопки в рамочках, а подписи с чертой, которая вырастает
от левого края и у текущей страницы уже проведена. Рамка вокруг каждого
пункта спорила с миллиметровкой: на клетчатом фоне и так хватает
прямоугольников.

Главное действие (`.btn--cta`) чёрное со светлым текстом. Ультрамарин из
палитры никуда не делся — им по-прежнему набраны ссылки, кольцо фокуса,
ползунки и полоса прогресса; чёрной стала именно кнопка. Чтобы она не
слилась с остальными чёрными кнопками, на наведение внутри проступает
тонкий светлый кант, а текст остаётся светлым. Контраст бумаги на чернилах
17:1 — с большим запасом к норме.

Кириллица у всех трёх проверена, а не предположена: запросом
`https://fonts.googleapis.com/css2?family=<имя>:wght@400` и поиском подстроки
`cyrillic` в ответе. Проверка не лишняя — у Newsreader, Fraunces, Archivo,
Space Grotesk, Instrument Sans и Spline Sans Mono на Google Fonts кириллицы
нет вовсе, и на русском тексте они молча подменяются системным шрифтом.
Сравнить кандидатов на настоящем заголовке сайта можно в `lab/type.html`.

Лежат в проекте: файлы в `assets/fonts/`, подключение в
`assets/css/fonts.css` (с 17.09.2026, до этого грузились с Google Fonts).
Внешних запросов нет — адрес посетителя не уходит Google (GDPR), сайт
работает офлайн, а первый текст на медленном мобильном интернете
появляется на 2–3 секунды раньше. Наборы символов: кириллица, латиница,
расширенная латиница. Лицензия всех трёх — SIL OFL 1.1.
Стенд `lab/type.html` по-прежнему берёт кандидатов с Google Fonts:
он служебный и в навигацию сайта не входит.

## Как прогнать проверки

Каждый стенд из `lab/` — обычная страница: откройте её в браузере и прочитайте
вердикт в рамке сверху. Он же дублируется в заголовок вкладки, поэтому весь
набор снимается одной командой без единого скриншота:

```powershell
$edge = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
$tmp  = Join-Path $env:TEMP "roy-check.html"
foreach ($t in 'pages','a11y','keys','search','fade','stage','motion','perf') {
  & $edge --headless=new --disable-gpu --allow-file-access-from-files `
          --virtual-time-budget=90000 --dump-dom "file:///C:/Проэкты/roy/lab/$t.html" |
    Out-File -FilePath $tmp -Encoding utf8
  $m = [regex]::Match((Get-Content $tmp -Raw), '<div id="sum">([^<]*)')
  "{0,-8} {1}" -f $t, $m.Groups[1].Value
}
```

Две вещи, на которых это ломается, если переписывать команду:

- **Флаг `--allow-file-access-from-files` обязателен.** Стенды читают страницы
  сайта в iframe, а по `file://` без него каждый документ для браузера — чужое
  происхождение, и стенд молча покажет пустую таблицу.
- **Вывод `--dump-dom` надо пропустить через файл.** Прямо в переменную
  (`$out = & $edge …`) он в PowerShell не попадает: переменная остаётся
  пустой, и вердикт «теряется», хотя проверки прошли.

Ругань Edge в stderr про `fallback_task_provider` и `GetUpdates` к делу не
относится — это его собственные сообщения, они есть всегда.

Последний прогон:

```

a11y     ВСЁ ЧИСТО: замечаний нет на 10 страницах
keys     ПРОХОД ЧИСТЫЙ: 9 страниц
search   ПОИСК В ПОРЯДКЕ: 12 запросов
fade     ПЕРВЫЙ ЭКРАН В ПОРЯДКЕ: 7 проверок
stage    СТОП-КАДР В ПОРЯДКЕ: 7 проверок
motion   ВЫКЛЮЧЕННОЕ ДВИЖЕНИЕ В ПОРЯДКЕ: 9 проверок
perf     ПЛАВНОСТЬ В ПОРЯДКЕ
```

## Что проверено

- Двадцать четыре симуляции работают, параметры меняют систему мгновенно и
  без перезапуска.
- Кнопка «Показать» под абзацем урока уводит параметр к нужному значению
  плавно, за полторы секунды, а не мгновенным скачком. Сама по себе от
  прокрутки сцена не меняется — см. раздел выше.
- Стая держится на дистанции 12 000 шагов, не разваливается и не схлопывается.
- При сплочённости 0 стая действительно рассыпается: разброс растёт с 174 до 240.
- Реакция-диффузия даёт визуально несовместимые узоры на разных `f` и `k`.
- Пробка и дюна показывают волновую природу на диаграмме «пространство —
  время»: полосы наклонены, значит форма движется, а не вещество.
- Мыльная плёнка сходится к сети Штейнера с углами 120° в каждом узле.
- Саранча даёт слаженность 0,77–0,91 из 1 выше порога плотности
  и распадается ниже него — измерено численно, а не на глаз.
- Невидимые сцены не считаются; уход на другую вкладку останавливает всё,
  возврат не прокручивает симуляцию вперёд.
- Сохранённый опыт открывается с теми же параметрами по ссылке: проверен
  полный круг «адрес → сцена → ссылка на опыт», значения совпадают.
- При выключенном движении сцена стоит, но ползунок её пересчитывает и
  перерисовывает — проверено сравнением содержимого холста до и после.
- Формы валидируются, состояние ошибки объявляется через `role="alert"`.
- `localStorage` работает по `file://` — прогресс и опыты сохраняются даже
  при открытии двойным кликом.
- Контраст текста проверен по WCAG: серый `#6E7278` на бумаге даёт 4,7:1.
  Светлый `#B9BCB6` давал 1,9:1 и как цвет текста больше не используется —
  только для границ.
- Плавность проверена по трём осям (`lab/perf.html`): цена кадра восьми самых
  тяжёлых симуляций на всех пяти ступенях — вместе 25,1 мс на верхней против
  4,8 на нижней, в 5,3 раза дешевле; цена первых двадцати кадров против
  установившихся — 5,5 против 4,5 мс; поведение регулятора на пяти
  последовательностях кадров — ровные 60 не трогают ступень, ровные 45 уводят
  до нижней, одиночный провал в 120 мс игнорируется, плохой прогрев тоже.
- Все 32 страницы отрисовывают своё содержимое (`lab/pages.html`): у каждой
  непустой h1, у каталога 24 карточки, у каждого урока ползунки, у открытых
  уроков ещё и кнопки «Показать», у листа — линейки для ответов. Упавший
  скрипт эти узлы не построил бы, так что проверка заменяет чтение консоли,
  которую headless не отдаёт.
- Выключенное движение проверено девятью проверками (`lab/motion.html`):
  вступления нет и текст виден сразу, «Запустить» показано и на главной, и
  на уроке, стоп-кадр знает, что сцена стоит, ползунки всё равно
  пересчитывают картинку, миниатюры в каталоге нарисованы.
- Надпись из стаи читается и не застывает (`lab/morph.html`): 2600 птиц по
  2600 точкам контура, после схождения каждая птица за секунду проходит
  1,8 px и держится в 1,6 px от своей точки. Первое — что стая живая,
  второе — что буквы при этом не расплываются.
- Тон бумаги не зависит от размера стаи: средняя яркость холста после 900
  шагов — 248 из 251 при 600 птицах и 243 при 2600.
- Правая колонка урока прокручивается отдельно: при 1240×760 содержимое
  1407 px, видно 676, прокручивается ровно на разницу.
- Проход с клавиатуры проверен на девяти страницах (`lab/keys.html`): первая
  остановка Tab — ссылка «перейти к содержанию», положительных `tabindex` нет,
  у каждой остановки есть имя, внутри `aria-hidden` фокусируемого нет, и
  порядок обхода совпадает с порядком на экране внутри каждой группы.
- Стоп-кадр на уроке проверен семью проверками (`lab/stage.html`): состояние
  кнопки и `aria-pressed`, пересчёт холста от ползунка при остановленной
  сцене, попадание параметра в ссылку на опыт, возврат к движению, сброс.
- Первый экран проверен семью проверками (`lab/fade.html`): на старте текст
  спрятан, не ловит курсор и не попадает в обход Tab; через четыре секунды
  без единой прокрутки он выходит сам; прокрутка тоже выводит его; при
  возврате к самому верху он не прячется обратно; переход объявлен в 240 мс.
- Поиск по каталогу проверен двенадцатью запросами (`lab/search.html`):
  словоформы (`светляк` находит «светлячков»), два слова через И, регистр и
  ё/е, научные термины из списка синонимов, пустой результат, а также то,
  что разметка из запроса не попадает в вывод.
- Аудит доступности (`lab/a11y.html`) проходит чисто на десяти страницах:
  один h1, ровный порядок заголовков, ярлык у каждого поля, текстовая
  альтернатива у каждого холста, язык страницы.
- Нагрузка каталога измерена: восемь тяжёлых миниатюр разом стоили 1,9 мс
  на кадр, с ограничителем — 0,6 мс при бюджете 16,7 мс.
- Внутренние ссылки и пути к файлам проверены — битых нет.
- Сайт открывается двойным кликом по `index.html`.

### Что проверить нельзя без реальных условий

- **Кадры в секунду на настоящей слабой машине.** Headless-браузер не даёт
  измерить fps: он отдаёт единицы кадров. Измерено другое, и этого немало:
  цена кадра каждой симуляции на каждой ступени (`lab/perf.html`), цена самых
  первых кадров страницы, поведение регулятора на выдуманных
  последовательностях кадров. Но подтвердить, что на конкретном школьном
  компьютере выходит именно 60, можно только на нём через вкладку Performance.
- **Первые три секунды на главной заголовка не видно.** Это цена вступления:
  пока стая складывается в надпись, `h1` спрятан и в дерево доступности не
  попадает. Смягчено тем, что текст выходит сам по таймеру, что первый же
  Tab выводит его немедленно и что при выключенном движении вступления нет
  вовсе. Убрать разрыв совсем можно только отказавшись от вступления.
  Поэтому `lab/a11y.html` даёт странице четыре с половиной секунды устояться:
  аудит судит то состояние, в котором читатель остаётся, а не первый кадр.
- **Экранный диктор.** Порядок обхода Tab и имена остановок теперь считаются
  машинно (`lab/keys.html`), но как это звучит вслух — вопрос отдельный:
  нужен любой диктор на одном-двух уроках. Машина не слышит, что
  «Стоп-кадр / Продолжить» объявляется понятно, а живая область урока
  (`aria-live`) не тараторит на каждое движение ползунка.
- **Видимость кольца фокуса на плохом мониторе.** Правило `:focus-visible`
  есть и даёт ультрамариновое кольцо в 2 пикселя, но контраст кольца на
  дешёвой матрице проектора проверяется только глазами.
- **Оплата, аккаунты, отправка форм** — нужен сервер.
- **Поведение с реальным доменом** — `canonical`, `og:image`, карта сайта.

## Безопасность

Что сделано в пределах статики:

- Никаких ключей, токенов и приватных адресов в коде.
- Данные банковских карт не принимаются и не хранятся ни при каких условиях.
- Пользовательский ввод не попадает в `innerHTML`: значения ползунков
  приводятся к числу и ограничиваются диапазоном, коды доступа выводятся
  через `textContent`.
- Ошибки хранилища перехватываются: в приватном режиме сайт продолжает
  работать, просто ничего не запоминает.
- Внешних скриптов нет вообще; единственный внешний ресурс — шрифты.

Что обязательно сделать при размещении:

- HTTPS и HSTS.
- Заголовки: `Content-Security-Policy` (минимум `default-src 'self'`,
  `style-src 'self' 'unsafe-inline'`, `font-src 'self'`),
  `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: strict-origin-when-cross-origin`,
  `Permissions-Policy: camera=(), microphone=(), geolocation=()`.
- Валидация и нормализация всего ввода на сервере, ограничение частоты
  запросов и защита форм от спама.
- Проверка прав на сервере, а не только в интерфейсе.
- Резервное копирование и обновление зависимостей на стороне бэкенда.

Утверждать, что сайт невозможно взломать, нельзя. Статика уменьшает
поверхность атаки, но всё существенное появится вместе с сервером — и
проверять нужно будет именно его.

## Доступность

- Разметка семантическая, у каждой страницы одна `h1`, заголовки по порядку.
- Навигация с клавиатуры работает везде, фокус виден (`:focus-visible`).
- У каждого ползунка настоящий `<input type="range">` с подписью, подсказкой
  через `aria-describedby` и видимым числовым значением.
- У каждой сцены есть текстовое описание происходящего, оно обновляется
  через `aria-live` — для тех, кто не видит холст.
- `prefers-reduced-motion: reduce` — сцены не запускаются сами, вместо этого
  кнопка «Запустить»; ползунки продолжают работать и пересчитывают систему.
  В кабинете есть отдельный переключатель на три положения.
- Ничего не мигает: вспышек чаще трёх раз в секунду нет нигде.
- Звука нет вообще.
- Размер шрифта переключается в кабинете, вёрстка не ломается.

## Известные ограничения

- Готовы все двадцать четыре урока: у каждого работающая симуляция, текст
  по правилам, схемы и вопросы. Девять открыты без подписки.
- Рабочие листы собираются из самого урока, отдельных файлов нет — поэтому
  они физически не могут разойтись с содержанием урока.
- Схемы в разделе «Где это в природе» нарисованы кодом. Это чертежи, а не
  фотографии: они показывают механизм. Фотографии можно добавить рядом, но
  только с подтверждённой лицензией.
